- **Tuning keys** name entries in the planned tuning data file (not created yet).

  claim_radius, king {id, name?, last_pos, seen_tick}, status (active|ruined), tier, stockpile {resource: count},
  buildings [{structure, pos, facing, state (planned|building|built)}], census {population, tick}, renown,
  founded_tick, chronicle [{time, text}]. No migration needed (new file). A future version 2 must convert version 1
  in `KingdomSavedData.load` and raise `DATA_VERSION`.
- **Kingdoms, data version 2** (stage 4, 2026-10-13): a building gets `level` (the structure's detail level, a
  positive number). Version 1 files read as they are: a building without `level` is level 1 (an optional field with a
  default), so no conversion is needed.
- **Kingdoms, data version 3** (stage 6, 2026-10-17): a kingdom gets an optional `plan` (D105): {center [x, z], keep
  [minX, maxX, minZ, maxZ], front (north|east|south|west), plots [{key, kind (building|later|waterside), outer, facing,
  easel_x, easel_z, rect}], roads [{from, to, width}], wall_corners [[x, z]], gates [{at, side}], claim_radius}. Version
  1 and 2 files read as they are: no `plan` means none yet (a kingdom whose keep is finished and has no other building
  draws one up). The claim radius may now grow once, to hold the plan.

  = `{csr_data_version: 1, jobs: [{easel: long, material: block id, planned: [long], placed: [long], columns: bool}]}`
  (positions as `BlockPos.asLong`). No migration needed (new file). A newer version is kept unchanged and read-only.
